Padrão ADAPTER (Adaptador): Integrando o Incompatível

Fazendo Interfaces Diferentes Trabalharem Juntas

🔌

O padrão Adapter permite que classes com interfaces incompatíveis trabalhem juntas, convertendo a interface de uma classe em outra interface esperada pelo cliente.

❓ Problema que Resolve

Você precisa usar uma classe existente, mas sua interface não é compatível com o resto do seu código. Reescrever não é uma opção!

🔄

Reutilização

Permite usar código legado sem modificá-lo

🔌

Compatibilidade

Conecta sistemas com interfaces diferentes

🛡️

Proteção

Isola mudanças em bibliotecas externas

Analogia do Mundo Real: Adaptador de Tomada

Viagem Brasil → Europa

🇧🇷 NO BRASIL
🔌
  • Tomada Tipo N: 3 pinos redondos
  • Voltagem: 110V ou 220V
  • Seu carregador: Funciona perfeitamente!
🇪🇺 NA EUROPA
⚡
  • Tomada Tipo C: 2 pinos redondos
  • Voltagem: 230V
  • Problema: Seu carregador NÃO encaixa!

🔌 Solução: ADAPTADOR DE TOMADA

Você compra um adaptador que:

  • Recebe seu plugue brasileiro (interface antiga)
  • Converte para o formato europeu (interface nova)
  • Você NÃO precisa trocar seu carregador!
  • O adaptador faz a "tradução" entre as interfaces

📌 Conclusão: O padrão Adapter funciona exatamente assim no código! Ele "adapta" uma interface antiga para uma nova, sem modificar o código original.

Adapter - Estrutura e Componentes

👤

Client

Código que precisa usar um serviço específico

📋

Target Interface

Interface que o cliente espera

🔌

Adapter

Converte interface do Adaptee para Target

📦

Adaptee

Classe existente com interface incompatível

🔄 Fluxo de Funcionamento
1

Client chama método na interface Target

↓
2

Adapter recebe a chamada e traduz para o método do Adaptee

↓
3

Adaptee executa a operação com sua interface original

↓
4

Adapter retorna resultado ao Client

Adapter - Exemplo Prático em Código

Cenário: Sistema Novo (JSON) precisa integrar com API Antiga (XML)

// Interface que nosso sistema espera (Target)
interface DataProcessor {
    processData(jsonData: string): void;
}

// Classe legada que só trabalha com XML (Adaptee)
class LegacyXMLParser {
    parseXML(xmlData: string): void {
        console.log("Processando XML: " + xmlData);
        // Lógica complexa de processamento XML...
    }
}

// ADAPTER: Converte JSON para XML
class XMLAdapter implements DataProcessor {
    private xmlParser: LegacyXMLParser;
    
    constructor() {
        this.xmlParser = new LegacyXMLParser();
    }
    
    processData(jsonData: string): void {
        // Converte JSON para XML
        let xmlData = this.convertJSONtoXML(jsonData);
        // Chama o método do sistema legado
        this.xmlParser.parseXML(xmlData);
    }
    
    private convertJSONtoXML(json: string): string {
        // Lógica de conversão...
        return "" + json + "";
    }
}

// USO
let processor: DataProcessor = new XMLAdapter();
processor.processData('{"nome": "João"}'); // Sistema novo usa JSON!
// Adapter traduz para XML e chama o sistema legado

💡 Vantagens: O código cliente (novo) não precisa saber que está falando com um sistema XML (antigo). O Adapter faz toda a "tradução"!

Padrão FACADE (Fachada): Simplificando o Complexo

Uma Interface Simples para um Sistema Complexo

🏢

O padrão Facade fornece uma interface simplificada para um conjunto complexo de classes, subsistemas ou bibliotecas.

❓ Problema que Resolve

Seu código precisa interagir com múltiplos subsistemas complexos. Chamar diretamente cada classe torna o código difícil de entender e manter.

✨

Simplicidade

Interface fácil de usar para operações comuns

🔒

Encapsulamento

Esconde a complexidade interna do sistema

🎯

Desacoplamento

Reduz dependências entre cliente e subsistemas

Analogia: Home Theater - Com e Sem Facade

❌ SEM FACADE

Para assistir um filme você precisa:

  • 1️⃣ Ligar a TV
  • 2️⃣ Selecionar entrada HDMI 2
  • 3️⃣ Ligar o amplificador
  • 4️⃣ Ajustar volume para 65
  • 5️⃣ Selecionar entrada do amplificador
  • 6️⃣ Ligar o Blu-ray player
  • 7️⃣ Inserir o disco
  • 8️⃣ Diminuir as luzes
  • 9️⃣ Dar play

😩 9 passos! Muito complexo!

✅ COM FACADE

Você usa um controle universal:

🎬
Botão "ASSISTIR FILME"

😊 1 clique! O Facade faz todo o resto!

📌 Conclusão: O Facade esconde toda a complexidade e oferece uma interface simples. No código, funciona da mesma forma!

Facade - Exemplo Prático: Sistema de E-commerce

Simplificando o processo de finalização de compra

// Subsistemas complexos
class InventorySystem {
    checkStock(productId: string): boolean { /* ... */ }
    reserveProduct(productId: string): void { /* ... */ }
}

class PaymentSystem {
    processPayment(amount: number, card: string): boolean { /* ... */ }
}

class ShippingSystem {
    calculateShipping(address: string): number { /* ... */ }
    scheduleDelivery(orderId: string): void { /* ... */ }
}

class NotificationSystem {
    sendEmail(to: string, message: string): void { /* ... */ }
    sendSMS(phone: string, message: string): void { /* ... */ }
}

// FACADE: Interface simplificada
class CheckoutFacade {
    private inventory = new InventorySystem();
    private payment = new PaymentSystem();
    private shipping = new ShippingSystem();
    private notification = new NotificationSystem();
    
    // UM método simples que orquestra tudo
    completeOrder(productId: string, card: string, address: string, email: string): boolean {
        // 1. Verifica estoque
        if (!this.inventory.checkStock(productId)) {
            return false;
        }
        
        // 2. Reserva produto
        this.inventory.reserveProduct(productId);
        
        // 3. Calcula frete
        let shippingCost = this.shipping.calculateShipping(address);
        
        // 4. Processa pagamento
        if (!this.payment.processPayment(100 + shippingCost, card)) {
            return false;
        }
        
        // 5. Agenda entrega
        this.shipping.scheduleDelivery("ORDER123");
        
        // 6. Envia confirmação
        this.notification.sendEmail(email, "Pedido confirmado!");
        
        return true;
    }
}

// USO: Super simples!
let checkout = new CheckoutFacade();
checkout.completeOrder("PROD123", "4111...", "Rua A, 123", "email@example.com");

Padrão OBSERVER (Observador): Sistema de Notificações

Comunicação Um-para-Muitos

👀

O padrão Observer define uma dependência um-para-muitos entre objetos, onde quando um objeto muda de estado, todos os seus dependentes são notificados e atualizados automaticamente.

❓ Problema que Resolve

Como notificar múltiplos objetos sobre mudanças em outro objeto, sem criar forte acoplamento entre eles?

🔔

Notificação Automática

Observadores são avisados automaticamente

➕

Flexibilidade

Adicione/remova observadores em runtime

🔓

Baixo Acoplamento

Subject não conhece detalhes dos observers

Analogia: Assinatura de Jornal / Canal do YouTube

📰

JORNAL (Subject/Publisher)

  • Publica notícias diariamente
  • Mantém lista de assinantes
  • Quando há nova edição, NOTIFICA todos os assinantes
  • Não se importa com o que cada assinante faz com o jornal
👤

ASSINANTE 1 (Observer)

Recebe o jornal e lê durante o café da manhã

👤

ASSINANTE 2 (Observer)

Recebe o jornal e lê apenas os esportes

👤

ASSINANTE 3 (Observer)

Recebe o jornal e usa para embalar objetos frágeis

📺 Exemplos do Dia a Dia

  • YouTube: Você se inscreve em um canal → recebe notificação de novos vídeos
  • Newsletter: Você assina → recebe e-mails quando há novos artigos
  • Redes Sociais: Você segue alguém → é notificado de novos posts

Observer - Estrutura e Componentes

📢

Subject (Publisher)

Objeto observado que notifica mudanças

👀

Observer Interface

Define método update() para receber notificações

📧

Concrete Observers

Implementações específicas que reagem às notificações

🔄 Fluxo de Funcionamento
1

Observer se registra no Subject: subject.subscribe(observer)

↓
2

Subject adiciona observer à lista de inscritos

↓
3

Estado do Subject muda (novo evento ocorre)

↓
4

Subject chama notify(), que itera sobre todos observers

↓
5

Cada Observer recebe update() e reage conforme sua lógica

Observer - Exemplo Prático: Sistema de Notícias

Múltiplos canais de notificação (Email, SMS, App)

// Interface Observer
interface NewsSubscriber {
    update(news: string): void;
}

// Concrete Observers
class EmailSubscriber implements NewsSubscriber {
    private email: string;
    
    constructor(email: string) {
        this.email = email;
    }
    
    update(news: string): void {
        console.log(`📧 Enviando e-mail para ${this.email}: ${news}`);
    }
}

class SMSSubscriber implements NewsSubscriber {
    private phone: string;
    
    constructor(phone: string) {
        this.phone = phone;
    }
    
    update(news: string): void {
        console.log(`📱 Enviando SMS para ${this.phone}: ${news}`);
    }
}

class AppNotificationSubscriber implements NewsSubscriber {
    private userId: string;
    
    constructor(userId: string) {
        this.userId = userId;
    }
    
    update(news: string): void {
        console.log(`🔔 Push notification para ${this.userId}: ${news}`);
    }
}

// Subject (Publisher)
class NewsPublisher {
    private subscribers: NewsSubscriber[] = [];
    
    subscribe(subscriber: NewsSubscriber): void {
        this.subscribers.push(subscriber);
    }
    
    unsubscribe(subscriber: NewsSubscriber): void {
        const index = this.subscribers.indexOf(subscriber);
        if (index > -1) {
            this.subscribers.splice(index, 1);
        }
    }
    
    notify(news: string): void {
        for (let subscriber of this.subscribers) {
            subscriber.update(news);
        }
    }
    
    publishNews(news: string): void {
        console.log(`📰 Notícia publicada: ${news}`);
        this.notify(news);
    }
}

// USO
let publisher = new NewsPublisher();

publisher.subscribe(new EmailSubscriber("user@email.com"));
publisher.subscribe(new SMSSubscriber("+5511999999999"));
publisher.subscribe(new AppNotificationSubscriber("USER123"));

publisher.publishNews("Brasil vence a Copa do Mundo!");
// Todos os 3 subscribers são notificados automaticamente!

Padrão STRATEGY (Estratégia): Algoritmos Intercambiáveis

Trocar Comportamento em Tempo de Execução

🎯

O padrão Strategy define uma família de algoritmos, encapsula cada um deles e os torna intercambiáveis. O cliente pode escolher qual algoritmo usar em tempo de execução.

❓ Problema que Resolve

Como trocar algoritmos/comportamentos dinamicamente sem usar múltiplos if/else ou switch gigantes? Como adicionar novos algoritmos sem modificar código existente?

🔄

Flexibilidade

Troque algoritmos em runtime

🧩

Elimina Condicionais

Substitui if/else e switch complexos

➕

Extensível

Adicione novos algoritmos sem quebrar código

Analogia: Métodos de Pagamento em E-commerce

❌ SEM STRATEGY
function processPayment(method: string, amount: number) {
    if (method === "credit_card") {
        // Lógica cartão de crédito
        // 50 linhas de código...
    } else if (method === "pix") {
        // Lógica PIX
        // 40 linhas de código...
    } else if (method === "boleto") {
        // Lógica boleto
        // 30 linhas de código...
    } else if (method === "paypal") {
        // Lógica PayPal
        // 45 linhas de código...
    }
    // ... mais métodos
}

😩 Função gigante! Difícil de manter!

✅ COM STRATEGY
// Cada método é uma classe separada
class CreditCardStrategy { pay() {...} }
class PixStrategy { pay() {...} }
class BoletoStrategy { pay() {...} }
class PayPalStrategy { pay() {...} }

// Cliente escolhe a estratégia
let payment = new PaymentProcessor();
payment.setStrategy(new PixStrategy());
payment.process(100.00);

// Trocar é fácil!
payment.setStrategy(new CreditCardStrategy());
payment.process(200.00);

😊 Organizado! Cada estratégia isolada!

💡 Vantagem: Adicionar novo método de pagamento = criar nova classe. Não precisa mexer no código existente!

Strategy - Estrutura e Componentes

💼

Context

Mantém referência à estratégia atual

📋

Strategy Interface

Define método comum para todas estratégias

🛠️

Concrete Strategies

Implementações específicas do algoritmo

🔄 Fluxo de Funcionamento
1

Context é criado (ex: PaymentProcessor)

↓
2

Cliente define qual Strategy usar: setStrategy(new PixStrategy())

↓
3

Context armazena referência à estratégia

↓
4

Quando necessário, Context delega execução para a Strategy

↓
5

Concrete Strategy executa seu algoritmo específico

Strategy - Exemplo Prático: Sistema de Pagamento

// Interface Strategy
interface PaymentStrategy {
    pay(amount: number): void;
}

// Concrete Strategies
class CreditCardStrategy implements PaymentStrategy {
    private cardNumber: string;
    private cvv: string;
    
    constructor(cardNumber: string, cvv: string) {
        this.cardNumber = cardNumber;
        this.cvv = cvv;
    }
    
    pay(amount: number): void {
        console.log(`💳 Pagando R$${amount} com Cartão de Crédito ${this.cardNumber}`);
        // Lógica de integração com operadora...
    }
}

class PixStrategy implements PaymentStrategy {
    private pixKey: string;
    
    constructor(pixKey: string) {
        this.pixKey = pixKey;
    }
    
    pay(amount: number): void {
        console.log(`💱 Pagando R$${amount} via PIX para chave ${this.pixKey}`);
        // Gera QR Code, aguarda confirmação...
    }
}

class BoletoStrategy implements PaymentStrategy {
    pay(amount: number): void {
        console.log(`📄 Gerando boleto de R$${amount}`);
        // Gera código de barras, data de vencimento...
    }
}

// Context
class ShoppingCart {
    private paymentStrategy: PaymentStrategy;
    private totalAmount: number = 0;
    
    setPaymentStrategy(strategy: PaymentStrategy): void {
        this.paymentStrategy = strategy;
    }
    
    addItem(price: number): void {
        this.totalAmount += price;
    }
    
    checkout(): void {
        if (!this.paymentStrategy) {
            console.log("❌ Escolha um método de pagamento!");
            return;
        }
        this.paymentStrategy.pay(this.totalAmount);
    }
}

// USO
let cart = new ShoppingCart();
cart.addItem(50.00);
cart.addItem(30.00);

// Cliente escolhe PIX
cart.setPaymentStrategy(new PixStrategy("meuemail@exemplo.com"));
cart.checkout(); // Paga R$80 via PIX

// Em outra compra, pode escolher cartão
cart.setPaymentStrategy(new CreditCardStrategy("1234-5678-9012-3456", "123"));
cart.checkout(); // Paga com cartão

Resumo: Quando Usar Cada Padrão?

Tabela Comparativa dos 4 Padrões

Padrão Categoria Quando Usar Problema que Resolve
Adapter Estrutural Interfaces incompatíveis Incompatibilidade entre sistemas
Facade Estrutural Subsistema muito complexo Complexidade excessiva
Observer Comportamental Múltiplos objetos reagindo a eventos Notificação automática
Strategy Comportamental Trocar algoritmo em runtime If/else ou switch complexos

🤔 Guia Rápido de Decisão

  • Integrar código incompatível? → Use ADAPTER
  • Simplificar sistema complexo? → Use FACADE
  • Notificar múltiplos objetos? → Use OBSERVER
  • Trocar algoritmo em runtime? → Use STRATEGY
