O que é Arquitetura de Software?

📐

Estrutura fundamental de um sistema de software que define seus componentes, suas relações e os princípios que orientam seu design e evolução.

Principais Aspectos
  • Define COMO o software será construído
  • Organiza componentes e suas interações
  • Conecta tecnologia e estratégia de negócio
  • Responde a requisitos funcionais e não funcionais

Componentes

Unidades modulares de software que encapsulam um conjunto de funcionalidades e dados relacionados.

Características
  • Possuem interfaces bem definidas
  • São independentes e substituíveis
  • Encapsulam lógica de negócio
  • Podem ser reutilizados em diferentes contextos
Exemplos

Módulos, Classes, Serviços, Bibliotecas, Bancos de Dados

Conectores

Mecanismos que mediam a comunicação, coordenação e cooperação entre componentes.

Serviços Fornecidos

🎯 Coordenação

Controle de fluxo

🔄 Conversão

Transformação de dados

🛠️ Facilitação

Serviços adicionais

Diferença: Componentes vs Conectores

Componentes

  • ✓ Realizam computação
  • ✓ Armazenam estado
  • ✓ Implementam lógica de negócio
  • ✓ Focam no QUE fazer

Conectores

  • ✓ Facilitam interação
  • ✓ Transferem dados e controle
  • ✓ Não possuem lógica de aplicação
  • ✓ Focam no COMO interagir

Configuração Arquitetural

A topologia que descreve como componentes e conectores são organizados e conectados para formar a estrutura do sistema.

Propósito
  • ✓ Define a estrutura geral do sistema
  • ✓ Especifica quais componentes estão conectados
  • ✓ Determina o padrão de comunicação
  • ✓ Estabelece hierarquias e dependências

Nota: A configuração pode ser estruturada hierarquicamente, permitindo múltiplos níveis de abstração.

Estilos Arquiteturais

🏛️

Padrões estabelecidos de organização de componentes e conectores que definem uma família de arquiteturas com características comuns.

Características
  • Vocabulário de tipos de componentes e conectores
  • Restrições sobre como podem ser combinados
  • Interpretação semântica para computação
  • Benefícios e trade-offs conhecidos

Importante: A escolha do estilo adequado impacta diretamente qualidade, manutenção e evolução do sistema.

Estilos vs Padrões Arquiteturais

Estilos Arquiteturais

  • ✓ Mais abstratos e genéricos
  • ✓ Definem estrutura geral
  • ✓ Aplicáveis ao sistema inteiro
  • ✓ Exemplo: Camadas, Cliente-Servidor

Padrões Arquiteturais

  • ✓ Mais específicos e concretos
  • ✓ Soluções para problemas recorrentes
  • ✓ Aplicáveis a partes do sistema
  • ✓ Exemplo: MVC, Repository, Factory

Arquitetura em Camadas

Layered Architecture

Organiza o sistema em grupos de subtarefas hierárquicas, onde cada camada fornece serviços para a camada superior e utiliza serviços da camada inferior.

Princípios Fundamentais
📚

Separação de responsabilidades

⬆️

Dependência unidirecional

Camadas Típicas

🖥️ Camada de Apresentação (UI)

Responsabilidade: Interface com o usuário

Funções: Exibição de dados, captura de entrada, validação básica

⚙️ Camada de Aplicação/Negócio

Responsabilidade: Lógica de negócio

Funções: Regras de negócio, processamento, orquestração

💾 Camada de Dados/Persistência

Responsabilidade: Gerenciamento de dados

Funções: CRUD, acesso a banco de dados, persistência

Camada de Apresentação (UI)

Responsabilidade Principal

Gerenciar a interação com o usuário, exibindo informações e coletando entrada de dados.

Funções-Chave
  • Renderizar interfaces visuais
  • Validar entrada de usuário (formato básico)
  • Formatar dados para exibição
  • Enviar comandos para camada de negócio

⚠️ O que EVITAR nesta camada:

  • Lógica de negócio complexa
  • Acesso direto ao banco de dados
  • Cálculos de regras de negócio
Exemplos de Implementação

HTML/CSS/JavaScript, React, Angular, Vue.js, Mobile Apps (iOS/Android)

✓

✓

Desvantagens da Arquitetura em Camadas

  • ⚠️
    Overhead de Performance

    Múltiplas camadas podem adicionar latência na comunicação

  • ⚠️
    Complexidade Adicional

    Para sistemas simples, pode ser excessivo

  • ⚠️
    Cascata de Mudanças

    Alterações em interfaces podem propagar entre camadas

  • ⚠️
    Rigidez

    Estrutura hierárquica pode limitar comunicação direta entre camadas não adjacentes

  • ⚠️
    Duplicação de Código

    Objetos de transferência entre camadas podem levar a redundância

Divisão Física vs Lógica

Divisão Lógica

  • ✓ Separação conceitual de responsabilidades
  • ✓ Todas as camadas no mesmo processo/servidor
  • ✓ Comunicação via chamadas de método
  • ✓ Exemplo: Aplicação monolítica
  • ✓ Vantagem: Mais simples e rápida

Divisão Física

  • ✓ Camadas executam em processos/servidores separados
  • ✓ Comunicação via rede (HTTP, RPC, etc.)
  • ✓ Permite escalabilidade independente
  • ✓ Exemplo: Frontend separado do Backend
  • ✓ Vantagem: Melhor escalabilidade e resiliência

Resumo dos Conceitos-Chave

  • Arquitetura de Software: Estrutura fundamental que define componentes, relações e princípios de design
  • Componentes: Unidades que realizam computação e armazenam estado (O QUE fazer)
  • Conectores: Mecanismos que facilitam interação entre componentes (COMO interagir)
  • Configuração: Topologia que organiza componentes e conectores
  • Estilos Arquiteturais: Padrões estabelecidos de organização com características comuns
  • Arquitetura em Camadas: Organização hierárquica com separação de responsabilidades
  • Camada de Apresentação: Gerencia interação com usuário
  • Camada de Negócio: Implementa lógica de negócio
  • Camada de Dados: Gerencia persistência e acesso a dados
