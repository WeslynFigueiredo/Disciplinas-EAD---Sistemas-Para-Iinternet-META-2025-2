🚫 Redundância e Anomalias: O Problema dos Dados Bagunçados

O que é Redundância?
Dados que são repetidos desnecessariamente na base de dados, causando problemas de atualização e consistência.
📋
Analogia da Planilha Bagunçada
É como uma planilha bagunçada onde você precisa atualizar a mesma informação em vários lugares. Se esquecer de atualizar uma célula, seus dados ficam inconsistentes e pouco confiáveis.

As 3 Anomalias de Dados

Problemas causados pela redundância que você precisa EVITAR:

❌
ANOMALIA DE INSERÇÃO
Impossibilidade de inserir dados incompletos
🗑️
ANOMALIA DE EXCLUSÃO
Perda de informações ao deletar um registro
⚠️
ANOMALIA DE ATUALIZAÇÃO
Inconsistência por repetição de dados
💡 Nos próximos slides, você verá exemplos VISUAIS de cada anomalia com tabelas!

❌ Anomalia de Inserção - Impossibilidade de Inserir

Definição: Você não pode inserir novos dados sem ter informações incompletas

Tabela: Vendas_Completa (VIOLADA)
ID_Vendedor Nome_Vendedor ID_Pedido Data_Pedido Valor
101 João Silva 5001 2025-01-15 1500
102 Maria Santos 5002 2025-01-16 2000
103 Pedro Costa NULL NULL NULL
🚫
PROBLEMA:
Você NÃO consegue adicionar um novo vendedor sem ter um pedido associado, ou vice-versa. Informação incompleta!

Consequência: Impossível cadastrar vendedores que ainda não fizeram nenhuma venda.

🗑️ Anomalia de Exclusão - Perda de Informações

Definição: Deletar um registro deleta também informações não relacionadas

Tabela: Vendas_Completa (VIOLADA)
ID_Vendedor Nome_Vendedor ID_Pedido Data_Pedido Valor
101 João Silva 5001 2025-01-15 1500
102 Maria Santos 5002 2025-01-16 2000
🚫
PROBLEMA:
Se você DELETA o pedido 5002, você também PERDE a informação de que 'Maria Santos' é uma vendedora!

Consequência: Informação importante é perdida permanentemente. O banco perde o registro da vendedora Maria Santos.

⚠️ Anomalia de Atualização - Inconsistência de Dados

Definição: Atualizar um dado causa inconsistência porque aparece em múltiplos lugares

Tabela: Vendas_Completa (VIOLADA)
ID_Vendedor Nome_Vendedor ID_Pedido Data_Pedido Valor
101 João Silva 5001 2025-01-15 1500
101 João Silva 5003 2025-01-17 3000
101 João Silva 5004 2025-01-18 2500
🚫
PROBLEMA:
Se 'João Silva' mudar de nome para 'João Pedro', você precisa atualizar em 3 lugares! Se esquecer 1, os dados ficam INCONSISTENTES.

Consequência: Banco de dados com informações conflitantes e pouco confiável. Qual é o nome correto?

📐 O que são Formas Normais? - Regras para Dados Bem Organizados

Definição
As Formas Normais (FNs) são um conjunto de testes e regras para verificar e melhorar a qualidade do design do Banco de Dados.
Progressão das Formas Normais
As FNs formam uma sequência progressiva:
1FN → 2FN → 3FN → BCNF → 4FN → 5FN
Cada uma é mais rigorosa que a anterior.
Objetivo
Eliminar redundância, anomalias e inconsistências através de uma estrutura de dados bem organizada.
💡 Nos próximos slides, você aprenderá 1FN, 2FN e 3FN com exemplos detalhados!

💭 Mito vs. Verdade - Desvendando Conceitos Sobre Formas Normais

❌ MITO 1
"Toda tabela deve estar na 5FN para ser perfeita"
✅ VERDADE
Na prática, 3FN ou BCNF são suficientes para a maioria dos casos. 4FN e 5FN são para situações muito específicas.
❌ MITO 2
"Normalização sempre melhora a performance"
✅ VERDADE
Normalização elimina redundância, mas pode aumentar complexidade e necessidade de JOINs. Às vezes, denormalização estratégica é necessária para performance.
❌ MITO 3
"Uma tabela não normalizada é sempre ruim"
✅ VERDADE
Para relatórios e data warehouses, às vezes mantemos dados denormalizados intencionalmente para melhor performance de leitura.

📦 Primeira Forma Normal (1FN) - Atomicidade

Definição
Uma tabela está em 1FN quando todos os seus atributos contêm apenas valores ATÔMICOS (indivisíveis) e não há grupos repetitivos.
Critério 1: ATOMICIDADE
Cada célula deve conter um único valor, não um conjunto ou lista
Critério 2: Eliminação de Grupos Repetitivos
Não deve haver campos que se repetem (como Telefone1, Telefone2, Telefone3)
💡 Próximo slide: Exemplo visual de violação de 1FN

🚫 1FN - Exemplo de Violação: Valores Não Atômicos

Tabela: Clientes (NÃO está em 1FN)
ID_Cliente Nome Telefones
1 João Silva (11) 98765-4321, (11) 3456-7890
2 Maria Costa (21) 99876-5432
3 Pedro Lima (31) 98765-4321, (31) 3456-7890, (31) 2345-6789
🚫
PROBLEMA:
O campo Telefones contém MÚLTIPLOS valores em uma única célula. Não é ATÔMICO!

Consequência: Impossível fazer buscas por telefone específico, queries ficam complexas.

✅ 1FN - Decomposição para Valores Atômicos

Tabela 1: Clientes (em 1FN)
ID_Cliente Nome
1 João Silva
2 Maria Costa
3 Pedro Lima
Tabela 2: Telefones_Cliente (em 1FN)
ID_Cliente Telefone
1 (11) 98765-4321
1 (11) 3456-7890
2 (21) 99876-5432
3 (31) 98765-4321
3 (31) 3456-7890
3 (31) 2345-6789
✅
SOLUÇÃO:
Cada telefone em sua própria linha. Valores ATÔMICOS apenas!

📐 Segunda Forma Normal (2FN) - Dependência Parcial

Pré-requisito
A tabela deve estar em 1FN
Conceito: Dependência Funcional
Dizemos que Y depende funcionalmente de X (X → Y) se cada valor de X tem um único valor de Y associado.
Definição 2FN
Uma tabela está em 2FN quando:
  • Está em 1FN E
  • Nenhum atributo não-chave depende parcialmente da chave primária (quando ela é composta)
O Problema: Dependência Parcial
Um atributo não-chave que depende de APENAS UMA PARTE da chave composta (não de toda a chave)

🚫 2FN - Exemplo de Violação: Dependências Parciais

Tabela: Itens_Pedido (Chave Composta: ID_Pedido + ID_Produto)
ID_Pedido ID_Produto Nome_Produto Preço Quantidade Data_Pedido
5001 101 Notebook 3500 2 2025-01-15
5001 102 Mouse 150 5 2025-01-15
5002 101 Notebook 3500 1 2025-01-16
5002 103 Teclado 350 3 2025-01-16
Dependências Funcionais VIOLANDO 2FN:
ID_Pedido → Data_Pedido (depende APENAS de ID_Pedido, não toda a chave)
ID_Produto → Nome_Produto (depende APENAS de ID_Produto, não toda a chave)
ID_Produto → Preço (depende APENAS de ID_Produto, não toda a chave)
🚫
PROBLEMA:
O campo Nome_Produto aparece repetido porque depende apenas de ID_Produto. REDUNDÂNCIA!

✅ 2FN - Decomposição para Eliminar Dependências Parciais

Tabela 1: Pedidos (em 2FN)
ID_Pedido Data_Pedido
5001 2025-01-15
5002 2025-01-16
Tabela 2: Produtos (em 2FN)
ID_Produto Nome_Produto Preço
101 Notebook 3500
102 Mouse 150
103 Teclado 350
Tabela 3: Itens_Pedido (em 2FN)
ID_Pedido ID_Produto Quantidade
5001 101 2
5001 102 5
5002 101 1
5002 103 3
Dependências Corretas (SEM PARCIAIS):
Pedidos: ID_Pedido → Data_Pedido ✓
Produtos: ID_Produto → Nome_Produto, Preço ✓
Itens_Pedido: (ID_Pedido, ID_Produto) → Quantidade ✓

🔗 Terceira Forma Normal (3FN) - Dependência Transitiva

Pré-requisito
A tabela deve estar em 2FN
Conceito: Dependência Transitiva
Um atributo não-chave depende de OUTRO atributo não-chave, que por sua vez depende da chave primária.
Chave Primária → Atributo Intermediário → Atributo Dependente
Definição 3FN
Uma tabela está em 3FN quando:
  • Está em 2FN E
  • Nenhum atributo não-chave depende transitivamente da chave primária

🚫 3FN - Exemplo de Violação: Dependência Transitiva

Tabela: Pedidos (Chave Primária: ID_Pedido)
ID_Pedido ID_Vendedor Nome_Vendedor Email_Vendedor Data_Pedido Valor
5001 101 João Silva joao@email.com 2025-01-15 1500
5002 102 Maria Santos maria@email.com 2025-01-16 2000
5003 101 João Silva joao@email.com 2025-01-17 1800
Dependências VIOLANDO 3FN:
ID_Pedido → ID_Vendedor (OK)
ID_Vendedor → Nome_Vendedor (Dependência entre não-chaves)
ID_Vendedor → Email_Vendedor (Dependência entre não-chaves)
CADEIA DE DEPENDÊNCIA TRANSITIVA:
ID_Pedido → ID_Vendedor → Nome_Vendedor
ID_Pedido → ID_Vendedor → Email_Vendedor
🚫
PROBLEMA:
Nome_Vendedor e Email_Vendedor aparecem repetidos para o mesmo vendedor. REDUNDÂNCIA e possíveis ANOMALIAS!

✅ 3FN - Decomposição para Eliminar Dependências Transitivas

Tabela 1: Pedidos (em 3FN)
ID_Pedido ID_Vendedor Data_Pedido Valor
5001 101 2025-01-15 1500
5002 102 2025-01-16 2000
5003 101 2025-01-17 1800
Tabela 2: Vendedores (em 3FN)
ID_Vendedor Nome_Vendedor Email_Vendedor
101 João Silva joao@email.com
102 Maria Santos maria@email.com
Dependências Corretas (SEM TRANSITIVAS):
Pedidos: ID_Pedido → ID_Vendedor ✓ (sem transitiva)
Vendedores: ID_Vendedor → Nome_Vendedor, Email_Vendedor ✓ (sem transitiva)
