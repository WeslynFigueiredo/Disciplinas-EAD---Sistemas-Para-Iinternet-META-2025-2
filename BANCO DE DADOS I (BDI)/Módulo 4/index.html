⚙️ Comando UPDATE - Modificando Dados Existentes

Definição
O comando UPDATE modifica os VALORES de uma ou mais colunas em linhas EXISTENTES de uma tabela.
📝
Analogia
É como usar uma borracha e reescrever informações em fichas de cadastro que já existem no arquivo.
Sintaxe Básica:
UPDATE nome_tabela
SET coluna = novo_valor
WHERE condição;
Estrutura em 3 Partes:
  1. UPDATE nome_tabela
    → Define QUAL tabela será modificada
  2. SET coluna = novo_valor
    → Define QUAIS colunas serão alteradas e seus NOVOS valores
  3. WHERE condição
    → Define QUAIS linhas serão afetadas
    ⚠️ EXTREMAMENTE IMPORTANTE!

UPDATE - Sintaxe e Exemplos

Exemplo 1 - Atualizar uma coluna específica:
UPDATE produtos
SET preco = 150.00
WHERE id = 10;
Explicação:
  • Tabela: produtos
  • Modifica: preco para 150.00
  • Apenas a linha onde id = 10
Exemplo 2 - Atualizar múltiplas colunas:
UPDATE clientes
SET email = 'novo@email.com', status = 'Inativo'
WHERE id = 25;
Explicação:
  • Modifica email E status
  • Apenas do cliente com id = 25
Exemplo 3 - Atualizar com cálculo:
UPDATE produtos
SET preco = preco * 1.10
WHERE estoque < 20;
Explicação:
  • Aumenta o preço em 10% (multiplica por 1.10)
  • Apenas produtos com estoque menor que 20

🚨 ALERTA CRÍTICO DE SEGURANÇA - UPDATE SEM WHERE

⚠️ PERIGO EXTREMO: UPDATE SEM WHERE ⚠️

Cenário Perigoso:
UPDATE produtos
SET preco = 0.00;
-- ❌ SEM WHERE!
Resultado CATASTRÓFICO:
TODOS os preços de TODOS os produtos são alterados para 0.00!
🔥
Analogia
É como entrar em uma biblioteca e RASGAR A MESMA PÁGINA de TODOS os livros ao mesmo tempo! Perda total de dados!
Regra de Ouro:
✅ SEMPRE use WHERE no UPDATE (a menos que você realmente queira modificar TODAS as linhas)
Exemplo Correto vs. Incorreto:
-- ❌ ERRADO - Todos os produtos ficam com preço 100
UPDATE produtos
SET preco = 100.00;

-- ✅ CORRETO - Apenas o produto ID=5 fica com preço 100
UPDATE produtos
SET preco = 100.00
WHERE id = 5;

🗑️ Comando DELETE - Removendo Dados

Definição
O comando DELETE remove linhas INTEIRAS de uma tabela. Diferente do UPDATE (que modifica), o DELETE APAGA completamente o registro.
📝
Analogia
É como pegar uma ficha de cadastro e JOGAR FORA completamente (não apenas apagar um campo).
Sintaxe Básica:
DELETE FROM nome_tabela
WHERE condição;
Estrutura em 2 Partes:
  1. DELETE FROM nome_tabela
    → Define DE QUAL tabela os registros serão removidos
  2. WHERE condição
    → Define QUAIS linhas serão removidas
    ⚠️ EXTREMAMENTE IMPORTANTE!
IMPORTANTE: DELETE remove a linha INTEIRA, não apenas um campo. Se você quer 'limpar' um campo, use UPDATE SET coluna = NULL.

🗑️ DELETE - Exemplos Práticos

Exemplo 1 - Deletar um registro específico
DELETE FROM clientes
WHERE id = 10;

Explicação:

  • Remove COMPLETAMENTE o cliente com id = 10
  • WHERE garante que apenas 1 registro seja afetado
  • A linha inteira é removida da tabela
Exemplo 2 - Deletar com múltiplas condições
DELETE FROM produtos
WHERE estoque = 0 AND preco < 10;

Explicação:

  • Remove produtos que têm estoque zero E preço menor que 10
  • Útil para limpar produtos descontinuados baratos
  • AND garante que AMBAS condições sejam verdadeiras
Exemplo 3 - Deletar registros antigos
DELETE FROM pedidos
WHERE data_pedido < '2020-01-01';

Explicação:

  • Remove todos os pedidos anteriores a 2020
  • Útil para arquivamento e limpeza de dados antigos
  • Operador < (menor que) funciona com datas
LEMBRE-SE: DELETE remove a linha INTEIRA. Se quiser apenas "limpar" um campo, use UPDATE SET campo = NULL.

🚨 ALERTA CRÍTICO - DELETE SEM WHERE

⚠️ PERIGO EXTREMO: DELETE SEM WHERE ⚠️

Cenário Perigoso:
DELETE FROM clientes;
-- ❌ SEM WHERE!
Resultado CATASTRÓFICO:
TODOS os clientes são DELETADOS! A tabela fica VAZIA!
🔥
Analogia
É como jogar TODO o arquivo de cadastros no INCINERADOR! Perda TOTAL e IRREVERSÍVEL (sem backup)!
Regra de Ouro:
✅ SEMPRE use WHERE no DELETE (a menos que você realmente queira apagar TUDO)
Dica Profissional:
Antes de executar DELETE:
1. Execute SELECT com o mesmo WHERE
2. Verifique QUANTAS linhas serão afetadas
3. Se estiver correto, substitua SELECT por DELETE

🎯 CRUD Completo - As 4 Operações Fundamentais

Resumo das Operações DML
CRUD SQL Ação
CREATE INSERT Criar novos registros
READ SELECT Ler/consultar dados
UPDATE UPDATE Atualizar dados existentes
DELETE DELETE Remover dados
Exemplos Práticos de Cada Operação:
-- CREATE
INSERT INTO clientes (nome, email) VALUES ('João', 'joao@email.com');

-- READ
SELECT * FROM clientes WHERE id = 1;

-- UPDATE
UPDATE clientes SET email = 'novo@email.com' WHERE id = 1;

-- DELETE
DELETE FROM clientes WHERE id = 1;
💼
CRUD no Dia a Dia
  • E-commerce: INSERT (novo produto), SELECT (listar), UPDATE (preço), DELETE (descontinuado)
  • Rede Social: INSERT (nova postagem), SELECT (feed), UPDATE (editar post), DELETE (remover)
  • Sistema Bancário: INSERT (nova conta), SELECT (saldo), UPDATE (atualizar dados), DELETE (encerrar conta)

🔗 Chave Estrangeira (Foreign Key)

Definição
Uma Chave Estrangeira (FK) é uma coluna que cria um LINK entre duas tabelas, apontando para a Chave Primária (PK) de outra tabela.
🏠
Analogia
É como o endereço de uma casa: você não escreve o endereço completo toda vez, apenas REFERENCIA ele. A FK é essa referência!
Exemplo Visual:

Tabela CLIENTES (PAI)

ID_Cliente (PK) Nome
1 João
2 Maria

Tabela PEDIDOS (FILHO)

ID_Pedido ID_Cliente (FK)
101 1 → João
102 2 → Maria

A FK ID_Cliente em PEDIDOS aponta para a PK ID_Cliente em CLIENTES

🛡️ Integridade Referencial

Definição
Integridade Referencial é a garantia de que as relações entre tabelas permaneçam CONSISTENTES. Se uma FK aponta para uma PK, essa PK DEVE EXISTIR.
Regras Principais:
  1. NÃO PODE inserir um FILHO sem PAI existente
    Exemplo: Não pode criar pedido do cliente ID=999 se esse cliente não existe
  2. NÃO PODE deletar um PAI que tenha FILHOS
    Exemplo: Não pode deletar cliente que tenha pedidos associados
🔒
Por que é Importante?
Sem integridade referencial, você poderia ter:
• Pedidos de clientes que não existem
• Dados órfãos (sem relacionamento)
• Inconsistências que quebram a aplicação
Exemplo de Bloqueio pelo SGBD:
-- Tentativa de INSERT filho sem pai
INSERT INTO pedidos (id_cliente, data) VALUES (999, '2024-01-01');
-- ❌ ERRO: Cliente 999 não existe!

-- Tentativa de DELETE pai com filhos
DELETE FROM clientes WHERE id = 1;
-- ❌ ERRO: Cliente 1 tem pedidos associados!

🔧 Foreign Key na Prática

Criando Tabelas com FK:
-- Tabela PAI (deve ser criada PRIMEIRO)
CREATE TABLE clientes (
    id INT PRIMARY KEY,
    nome VARCHAR(100)
);

-- Tabela FILHO (criada DEPOIS, referencia o pai)
CREATE TABLE pedidos (
    id INT PRIMARY KEY,
    id_cliente INT,
    data_pedido DATE,
    FOREIGN KEY (id_cliente) REFERENCES clientes(id)
);
O que a FK Garante:
  • ✅ Só pode inserir pedido se o cliente EXISTIR
  • ✅ Não pode deletar cliente que TEM pedidos
  • ✅ Dados sempre CONSISTENTES
  • ✅ SGBD bloqueia operações que violem a integridade
Operações Permitidas vs Bloqueadas:

✅ PERMITIDO

  • Inserir cliente novo
  • Inserir pedido de cliente existente
  • Deletar pedido
  • Deletar cliente SEM pedidos

❌ BLOQUEADO

  • Inserir pedido de cliente inexistente
  • Deletar cliente COM pedidos
  • Alterar FK para cliente inexistente

✅ Boas Práticas - UPDATE e DELETE Seguros

1. SEMPRE use WHERE
Nunca execute UPDATE ou DELETE sem WHERE, a menos que você REALMENTE queira afetar TODAS as linhas.
2. Teste com SELECT primeiro
-- 1. TESTE com SELECT
SELECT * FROM produtos WHERE estoque = 0;
-- Verifica: 15 linhas retornadas

-- 2. Se correto, execute DELETE
DELETE FROM produtos WHERE estoque = 0;
3. Use transações em operações críticas
BEGIN TRANSACTION;
    UPDATE contas SET saldo = saldo - 100 WHERE id = 1;
    UPDATE contas SET saldo = saldo + 100 WHERE id = 2;
COMMIT; -- Ou ROLLBACK se houver erro
4. Faça backup antes de operações em massa
Antes de deletar ou atualizar muitos registros, faça backup da tabela ou banco de dados.
5. Respeite a integridade referencial
Ao deletar, sempre delete os FILHOS antes dos PAIS. Ao inserir, sempre insira os PAIS antes dos FILHOS.
